## 选稿与解析标准

1. **原始来源优先**：官方公告与安全通告、项目仓库及 Release、作者论文与会议页面。二手报道可用于发现线索，核心技术判断尽量回到原始证据
2. **解释技术增量**：说明方法、架构、威胁模型、关键假设、与既有工作的差异及实践价值，避免把宣传语转述成结论
3. **核对实验边界**：指标注明数据集、基线、样本或评测范围；区分作者报告、独立验证与本文推断。未运行代码或复现实验时明确说明
4. **论文关注质量**：查看研究问题、方法、实验设计、消融、局限与可复现材料。预印本、已接收论文与正式发表分别标注，不把预印本默认视为已同行评审
5. **项目关注可用性**：核对许可证、维护活动、版本或提交、文档与复现条件、资源成本和已知限制。公开仓库但未见许可证时不直接称为可自由复用的开源项目；不凭 Star 数量判定质量
6. **训练评测看完整链路**：核对基础模型、数据来源与许可、训练 / 测试隔离及泄漏或基准污染风险；比较受控基线、消融与跨任务 / 环境迁移。记录训练与推理算力成本、模型权重 / 数据 / 环境的可获得性及许可证，不将基准高分直接等同于真实场景能力
7. **宁缺毋滥**：不强凑条数或三类配额。没有足够可靠的新内容就如实说明；无法访问全文、仓库或关键证据时记录限制，不写成已经完整阅读

## 每条内容如何读

- **一句话结论**：最值得注意的技术事实或变化
- **来源与时间**：原文标题、作者或机构、首次发布日期、事件发生日期、资料版本与核查时点。未知日期写“未明确”，不混用网页更新日、论文版本日和事件日
- **技术解析**：问题与威胁模型、方法、关键结果及成立条件
- **价值与边界**：适合谁、哪些场景可能有用、尚不能证明什么、落地或复现成本
- **证据状态**：分别说明“原始资料已核对”“作者自报”“独立验证”或“分析推断”；对核心结论给出高 / 中 / 低置信度及理由，不能将来源可信等同于结论已被复现
- **原始链接**：按用途列出论文、官方说明、仓库、Release、数据或评测；尽量保留 DOI、arXiv 版本、Release tag 或 commit SHA 等稳定标识

## 重复与更正

- 同一事件、论文或项目只保留一条主记录；同时出现论文、仓库和公告时互相链接，不按三个新成果重复计数
- 后续版本、补丁、重要实验或结论变化可以再次收录，但必须说明“本次新增”，并链接此前记录
- 更正保留原日报地址，在相关条目及文末写明更正时间、原因、影响与证据；实质性撤回或结论变化在后续日报提示，历史修改可通过 Git 记录追溯
- 断链时补充可核验的官方替代链接并说明，不悄悄更换所依据的证据
