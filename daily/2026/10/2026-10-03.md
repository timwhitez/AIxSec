### 1. SQL Copilot：数据库元数据成为指令后，只读意图必须落实为数据库权限

- **方向 / 类型 / 标签**：Sec4AI · news · `prompt-injection`、`agent-tool-security`、`data-exfiltration`
- **来源 / 真实日期**：Johann Rehberger，*From SELECT to SYSADMIN with SQL Copilot (CVE-2026-65669)*，技术披露 **2026-09-30**；初始研究始于 2026 年 5 月。微软漏洞通告与修复发布于 **2026-09-08**。**近期补读**，不算 10 月 3 日新漏洞
- **核心贡献判断**：这是“低信任内容影响高权限工具”的具体实现案例。最值得复用的认识是：能修改数据库说明文字的主体，可能获得影响另一个主体的 Agent 行为的机会；不能据标题推断只有 SELECT 权限就能无条件成为 sysadmin

**背景与问题。** SSMS Copilot 的数据库工具使用连接用户的身份。研究时的“只读”模式同时依靠模型指令和查询分类器；如果连接本身有写入或服务器管理权限，分类器失效后的 SQL 仍会由数据库合法执行。真正的问题是委托权限过大，提示词中的只读承诺没有在数据库中成为不可越过的限制。[研究全文](https://embracethered.com/blog/posts/2026/from-select-to-sysadmin-sql-copilot-bluehat-asia/) · [微软漏洞 FAQ](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-65669)

**核心新发现与机制。** 作者逆向定位到 `LocalSqlExecutionAccessChecker` 的正则分类，发现存储过程间接调用与动态 SQL 不受其预期约束；另一个备份验证工具也接受了任意 T/SQL。更重要的是，`AGENTS.md`、`CONSTITUTION.md` 以 extended properties（附加在数据库/对象上的说明属性）存储，会被自动加入 Copilot 上下文。对象 ALTER 权限可修改对象级说明；最终服务器角色提升演示则由 db_owner 放入数据库级说明，并等待高权限受害者使用 Copilot。两个场景的前提不同，不能合并成“任意低权限用户都能完整提权”。[原始机制与演示说明](https://embracethered.com/blog/posts/2026/from-select-to-sysadmin-sql-copilot-bluehat-asia/#indirect-prompt-injection-attack-paths)

**输入→处理→输出。** 输入是正常分析请求及数据库/文件上下文；Agent 将附加说明读成行为指令，生成工具参数；薄弱的只读检查没有阻止超出意图的查询，随后数据库按受害者连接权限执行，输出可能包含状态修改或出站副作用。这个链条不要求模型“获得新数据库权限”，而是借用了本来就存在但不应被不可信内容驱动的权限。这里仅解释边界，不转载载荷或提权语句。

**证据与修复比较。** 发现者给出代码逆向与直接、间接调用演示；微软确认 CVE-2026-65669 为 Critical，CVSS 3.1 基础分 9.6，明确需要用户交互、影响取决于连接用户权限，安全更新列出 SSMS **22.8.2**。这是漏洞机制与厂商处置证据，不是攻击成功率实验，也没有全部模型/配置的公平对照。[官方通告](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-65669)

**适用场景与可行动设计。** 对数据库 Agent，可先确认补丁版本，再把任务需要的权限授给专用低权限身份；审核的不仅是表数据读写，还包括谁能改变 Agent 将读取的对象/数据库说明。微软当前文档支持通过 `agentExecuteAsUser` 选择执行身份，采用 `EXECUTE AS`；操作者缺少对应 `IMPERSONATE` 时拒绝执行，不静默回退。但移除该配置后会恢复连接身份，因此配置漂移也需审计。Agent mode 的确认对话不是权限边界，工具名字叫“读”或“验证”也不代替服务器权限检查。[执行身份与失败行为](https://learn.microsoft.com/en-us/ssms/github-copilot/execution-context) · [管理控制](https://learn.microsoft.com/en-us/ssms/github-copilot/admin-controls)

**局限与判断。** 本轮核对研究全文、MSRC 动态通告、当前执行身份/管理文档及版本说明，未复现、未审厂商补丁代码，也没有证明当前所有工具均不可绕过。补丁解决已披露缺陷，最小权限则限制其他失效的后果；两者需要分别核查。机制和官方版本要求置信度高，模型间成功率与当前完整防护效果未知。

### 2. AuraForge：用攻击效果测试筛选安全 SFT 轨迹，质量与规模收益仍需拆开

- **方向 / 类型 / 标签**：AI4Sec · paper · `cyber-model-training`、`cyber-training-data`、`code-security`、`cyber-model-evaluation`
- **来源 / 真实日期**：Danqing Wang 等，*AuraForge: Scaling Security Supervision for Training Coding Agents*；[2610.00850v1](https://arxiv.org/abs/2610.00850v1)，提交 **2026-10-01 00:07:01 UTC**，列入 10 月 2 日公告。**近期补读**；预印本，未核实同行评审录用
- **核心贡献判断**：最值得借鉴的是可执行安全判定器和反参考答案检索设计。实际训练是成功轨迹筛选后的 SFT，论文把用测试奖励做 RL 列为未来工作，不能写成已经验证的 Cyber RLVR

**背景与问题。** 功能测试通过只说明代码完成所需行为，不说明恶意输入无法产生额外效果。安全训练又常受人工测试昂贵、真实修复实现只有一种、测试误把等价安全实现判错的限制。若拿历史补丁的外观当标准，就可能把“像参考答案”误当“安全”。AuraForge 将执行中能观察到的攻击后果变成监督信号，再选择真正通过功能与安全检查的 Agent 轨迹训练模型。[问题、方法与附录](https://arxiv.org/html/2610.00850v1)

**核心新想法与输入→处理→输出。** 输入真实漏洞修复提交，将仓库变为“实现功能、但不告知漏洞”的任务。测试生成分两阶段：先只读公开 CVE/公告，建立安全不变量、攻击入口与变体，不接触仓库；再进入漏洞版本生成效果测试，借历史补丁的应用/撤销获得执行反馈。生成器之外的新环境验收：无执行错误，至少一测试在漏洞版失败、修复版通过。输出合成安全测试及可筛选的任务/轨迹。相对特定错误字符串或 SQL 形状，观察攻击是否生效可接受不同的安全实现；但一个历史漏洞/修复对只能提供基本区分，不能保证任意新实现都被正确判定。[方法与验收](https://arxiv.org/html/2610.00850v1)

**数据构成与隔离。** AuraGym 合成版679任务、344仓库、177 CWE，人工测试版431任务、199仓库、139 CWE，覆盖Python/JS/TS。公开[数据卡](https://huggingface.co/datasets/dqwang122/AuraGym)明确两者互非子集：368任务共享、63仅人工、311仅合成，不宜照搬主文“人工子集”的简化说法。来源为 MoreFixes 与 GHSA；JS/TS 候选用2026-06-20 MoreFixes备份和冻结OSV npm快照，GHSA引用仍留有快照日期占位符。新增JS/TS评测82例按仓库隔离、69例来自2026年；训练也含2026数据，不能称严格时间切分。Python训练与SusVibes的完整隔离审计未给出。公开四个HF配置全标train、未单列验证/测试split；这不能证明或否定论文的JS/TS仓库隔离，应结合另行评测材料核实实际SFT子集和测试清单。数据卡也不保证与其他基准隔离。[数据与附录](https://arxiv.org/html/2610.00850v1)

**反作弊与 harness。** 解题阶段剥离git历史，清理安装包/构建产物中的参考实现，命令过滤限制网络及包下载；隐藏安全测试到独立新评测容器才引入，并过滤修改测试的补丁。旧的保留历史/网络环境中，作者审计5,174次SusVibes运行，16%出现参考实现检索；这不证明新环境已零泄漏。命令过滤也不等同操作系统级网络隔离。另剔除37个记录为pass但日志不支持的harness判定，说明学习信号的测试逻辑、执行隔离与日志解析需要分别校验。[环境审计及附录F](https://arxiv.org/html/2610.00850v1)

**安全判定器证据。** 作者在同批2,450个功能通过解答中标记635安全、1,815脆弱。人工→合成测试的 FPR 为16.7%→2.8%，漏洞召回98.3%→98.6%；FPR任务bootstrap的95%区间分别[12.0,22.0]、[1.0,5.0]。但2,271条共同判定直接当真值，共同漏报/误报不可见；分歧每任务最多审四条，35条未裁定。裁定靠隔离LLM Agent写攻击并执行，作者人工复核33条、推翻两条，未逐一外部人工确证。因此98.6%不是相对完整独立真值的保证。合成测试仍有25个漏判，13个集中在路径遍历/SSRF；DoS时间/内存阈值也会不稳定。[表2与裁定附录](https://arxiv.org/html/2610.00850v1)

**训练目标、模型增益与公平性。** 基座 Qwen3.5-4B，mini-swe-agent harness；DeepSeek-V4.1-Flash生成轨迹，合成条件保留594条、覆盖300任务做 SFT，学习成功动作序列，不是按可验证奖励在线 RL。部分采样先用CVE/CWE提示，训练前删除新增提示。训练64K上下文、batch8、3 epochs、峰值学习率1e-5；总GPU时、生成/测试费用、完整推理预算匹配及人工条件等样本预算未披露。

Python SusVibes（186例）的 FuncPass/SecPass：基座12.90/2.10，人工监督22.04/4.84，合成27.96/5.91；JS/TS（82例）分别12.19/0、32.93/6.10、36.59/8.54。SecPass以全部任务为分母，要求功能、安全都通过。两个评测集的非加权平均提升为19.7/6.2个百分点，不能写逐语言加权平均。共同harness下有权重后训练收益，但缺少等任务、等token、等教师采样及功能-only筛选对照，数据量、任务混合、测试质量仍混杂；安全绝对通过率仍低。30B及前沿模型是性能参照，不是预算匹配训练对照。[表3与训练附录](https://arxiv.org/html/2610.00850v1)

**可行动启发。** 授权安全编程训练可复用“攻击后果测试→独立执行验收→双通过轨迹筛选”的链路，并给每项判定保存执行证据。比较人工/合成监督时固定任务、轨迹token和教师采样预算，添加功能-only与安全筛选消融；给判定一致的样本也作外部抽查，才能发现共享错误。将数据扩量、harness修复、测试改进和模型学习分开报告，不以一个平均分为训练方法定性。

**阅读、可用性与判断。** 已读方法、主表、附录A–F及案例，核对数据卡并静态检查固定[SusVibes evaluator commit](https://github.com/LeiLiLab/susvibes/tree/520f16f9b3f39b06c6013bc0eb57a38280b4deee)的README、LICENSE、核心CLI、任务评分、安全测试路由及测试补丁过滤。未运行容器/代码、训练或独立复现，未审完整生成管线；数据卡也明示发布的完整容器执行未验证。论文CC BY4.0；作者材料MIT，上游代码/补丁及容器保留各自许可，逐库许可未全部核验，不能称全部数据无条件MIT。未核到配套微调权重或完整训练发布。方法与结果记录置信度高，测试真值和等预算泛化证据仍有限。

<a id="paper-absentia-route-invariant-audit"></a>
### 3. ABSENTIA：先把请求面列全，再逐路由反证业务授权关系

- **方向 / 类型 / 标签**：AI4Sec · paper · `code-security`、`vulnerability-discovery`、`security-agents`、`cyber-model-evaluation`
- **来源 / 真实日期**：André V. Duarte 等，*ABSENTIA: Detecting Broken Access Control Vulnerabilities in Web Applications*；[2610.00977v1](https://arxiv.org/abs/2610.00977v1)，提交 **2026-10-01 03:11:45 UTC**，列入 10 月 2 日公告。**近期补读**；预印本，未核实同行评审录用
- **核心贡献判断**：主要改进来自审计流程的覆盖与分解，不是模型训练。新增不变量步骤减少报告量的证据清楚；其精度增益尚未被论文的人类抽样验证确认

**背景与问题。** 污点分析擅长找“用户输入流进危险调用”，但授权缺陷常是缺少关系检查：用户已经登录，仍不应读取别人的账单。是否必须检查账单所有权由业务决定，单看登录装饰器或危险函数不够。无结构 Agent 又容易只读看起来可疑的文件，无法交代哪些入口没读。ABSENTIA 面向维护者授权的白盒代码审计，不需要部署应用、账号或访问线上接口。[问题与设计](https://arxiv.org/html/2610.00977v1#S3)

**核心新想法。** 先建立可枚举的请求面，再将每个路由交给独立读取过程：先写出它应满足的业务关系，找到执行检查的位置，最后尝试描述一个会违背该关系、但仍被代码接受的请求。相对“这个函数看起来不安全”的判断，报告必须给出候选规则、代码依据、前提和可观察后果；把模型的阅读能力组织成可复核的审计程序。[方法](https://arxiv.org/html/2610.00977v1#S4)

**输入→处理→输出与实现。** 输入是一份应用源代码。第一遍识别语言、框架、数据库和认证库；第二遍让两个抽取 Agent 分别找出此应用的路由/输入/权限检查/查询模式，合并后以确定性搜索构建文件和行号图，并展开 HTTP 方法。逐路由 Agent 读取 handler、调用到的服务与数据模型，输出符合固定字段的发现或不报告；最终可组合共享文件上的路由能力。再次审计时，只有依赖文件及导入扩展范围均未改变、且字节相同，才复用旧结论。实现使用 Strands、MiniMax-2.5，工具只读；它没有做 SFT/RL，也不运行目标应用。[实现与增量审计](https://arxiv.org/html/2610.00977v1#S6)

一个简短例子：账单路由有登录检查，模型仍须从账单数据模型识别“账单属于某账户”；沿调用链查找所有权约束，不能仅因 handler 没有该检查便认定漏洞，因为 middleware 或服务层可能已实施。请求面抽取不完整时，这个过程会完全漏掉某条路由。

**证据、消融与公平性。** BAC-Bench 包含 30 个已公开且已修复的授权漏洞，来自 25 仓库、3 语言、9 框架；成对计分要求旧版本报出指定漏洞、修复版本不再报同一漏洞。作者报告 ABSENTIA **19/30**，严格成对为 **17/30**；同模型自由 Agent **3/30**，CodeQL 与 Semgrep **0/30**。这是指定授权缺陷上的结果，不能推成传统工具在所有安全任务上无效。自由 Agent 最多 200 轮、平均用了 59 轮；全流程逐路由花费更多上下文和调用，未匹配总 token/成本，所以方法组织和覆盖预算仍有混杂。[主结果](https://arxiv.org/html/2610.00977v1#S7)

消融更能说明设计作用：加入逐路由分解达到 **18/30**，每实例平均 119 报告；加不变量反证为 **19/30**、77 报告。模型验证器对每配置/实例最多随机20条抽样的精度由 40.5% 升到 50.8%，但 73 条双方均认作授权问题的人类盲审中，确认率是 **无反证配置43% 对完整配置42%**，未重现增益。因此较稳的结论是“报告减少约三分之一，已知漏洞召回未观察到损失”，不是“精度已获独立确认”。27/30 漏洞入口进入图，剩余漏报主要在推理；更强模型只把已定位入口上的检出由19/27提高至22/27，没找回三条漏抽取路由。跨路由组合不是该基准30例召回的来源。[消融与人工核验](https://arxiv.org/html/2610.00977v1#S7.SS4)

**成本、使用条件与可行动启发。** 作者在其 Bedrock 费率下报告每仓库中位 **44 美元**、范围2–316美元，95%典型费用在逐路由读取；增量实验中位复用37%路由，这不等于端到端成本或耗时下降37%；该实验为了在第二次评分，用修复commit先分析、漏洞commit再分析，并非通常开发的正向顺序。适合先给自有后端建立路由→授权规则→代码依据的审计清单，并用漏洞/修复成对样本评估：只报漏洞版本还不足以证明理解修复。授权缺陷之外，Python/Java 注入样本的 FPR 分别0.42/0.62，意味着实际审查负担仍大，不能把高召回当自动放行上线的依据。[费用与边界](https://arxiv.org/html/2610.00977v1#S7.SS6)

**复现材料与局限。** 已读正文方法、主表、全部实验及附录A/B，核对[仓库README](https://github.com/avduarte333/Absentia)、[数据说明](https://github.com/avduarte333/Absentia/blob/main/data/README.md)和实际30条JSONL记录，计数与论文一致。仓库截至[80e30361](https://github.com/avduarte333/Absentia/commit/80e30361ebe3d6a779886ecb42a8ecbe7e75a561)只有公开基准和文档，README计划2026年底发布实现；未见LICENSE或Release，不能称检测器已开源可运行。论文是 arXiv 非独占分发许可。推理模型的准确训练截止未知，公告晚于某系列所述截止不能证明无污染；五次重复仅覆盖8个小实例，不能证明大型应用稳定。全部实验为作者报告，人工核验者也是作者；本轮未独立复现。流程设计证据中高，生产收益与完整复现性证据有限。

### 4. APEX：任务进展记录会把伪造授权带进下一个技能

- **方向 / 类型 / 标签**：Sec4AI · paper · `prompt-injection`、`agent-tool-security`、`ai-supply-chain`、`ai-security-evaluation`
- **来源 / 真实日期**：Tian Dong 等，*Chaining Skills to Hijack LLM Agents*；[2610.01564v1](https://arxiv.org/abs/2610.01564v1)，提交 **2026-10-01 12:28:49 UTC**，列入10月2日公告。**近期补读**；预印本，未核实同行评审录用
- **核心贡献判断**：正常任务验收通过，不能证明跨技能授权和副作用安全。价值在于定位交接记录中的“进展→授权”混淆；结果尚不能推导真实服务中全部目标副作用均已发生

**背景、威胁模型与新想法。** 多技能工作流会把上游文件作为下游输入。攻击者控制技能说明，知道任务主题和初始工作区，离线构造阶段可拿到执行反馈，但不直接进入受害者环境。APEX 将真实进展与虚假批准声明放进Agent自己产生的交接记录，使后续技能把“已经准备好”当成“被允许”。相对一次性的直接指令，它研究的是持久工件跨技能传递后，内容似乎获得了更可信来源的问题。[威胁模型与方法](https://arxiv.org/html/2610.01564v1)

**输入→处理→输出。** 输入合法任务、原生技能与一个指定越界目标；构建有记录交接的候选链，在隔离副本执行，分别收集族别目标证据与正常任务检查，再根据失败位置修订候选，输出链和评测证据。论文评估外发、外部辅助程序执行、指定原文件删除、输出篡改四类目标，并另测新工作单元循环的token成本。外发接收端是环境内捕获服务，不是现实收件人；这避免了研究对第三方真正发送数据，但限制了产品环境外推。[设计与评测](https://arxiv.org/html/2610.01564v1)

以“生成一份报告”为例，一条工件可准确写“报告数据已整理”，同时夹入与真实用户指令无关的“后续动作已获批准”。下游若把前一句可信事实的来源信用扩展到后一条权限声明，就会越过任务边界。本文只用这个抽象例子解释信任转移，不转载可执行攻击载荷。

**实验与消融。** SkillsBench六模型、四目标族合计690次评测，作者按其证据规则判定512次成功（74.2%）；每模型族别任务数30/29/25/31，同一原任务可在多族重复，不能当690个独立真实任务。GPT-5.4完整链97/115（84.3%），合并单技能17.4%，直接注入3.5%；将交接状态改成明确拒绝后仍27.0%。合并也改变指令分组与持久交接，拒绝版本增加禁令，不能将差距全归于一个授权字段；未见与ColluSkill/CompoSkill等强方法的匹配搜索预算直接比较。[主表与消融](https://arxiv.org/html/2610.01564v1)

**防御、效用与预算。** 提示模型把技能修改文件视为不可信、回查原请求，使GPT-5.4 ASR降至68/115（59.1%），仍有大量残余；72个无攻击原生任务的533项检查，通过率由462/533（86.7%）降至300/533（56.3%）。这说明提示级防护会损害正常操作，不能仅看ASR下降。防御只评固定攻击、未做适应性重构，也没有独立工具权限强制层。效用是检查项加权而非完整任务成功率。工作循环15任务、六模型的逐任务token比值均值2.20–36.39倍，不证明无限循环或违反明确预算；总搜索/生成费用、时延与预算匹配未完整披露。[防御、效用与成本附录](https://arxiv.org/html/2610.01564v1)

**实现核查与评分边界。** 已实际静态读取[adjudication.py](https://github.com/Minakamiii/Chaining_Skills_to_Hijack_LLM_Agents/blob/06360abbf1678d2b538c380f226b9541fa242e72/authority_promotion_explorer/chaining_skill/evaluation/adjudication.py)和[trace.py](https://github.com/Minakamiii/Chaining_Skills_to_Hijack_LLM_Agents/blob/06360abbf1678d2b538c380f226b9541fa242e72/authority_promotion_explorer/chaining_skill/evaluation/trace.py)：语义裁判之后还检查族别证据；删除族要求原生目标路径实际匹配，不把工作流新建文件算进去；执行族看受控监听连接，而非仅下载标记。不过外发成功函数也接受备用attempt-success旗标，本轮未追完其调用者；仍有LLM软语义判定。因此统计应表述为“按作者规则计分成功”，不能把所有ASR写成独立确认、已向真实系统交付数据。[官方仓库](https://github.com/Minakamiii/Chaining_Skills_to_Hijack_LLM_Agents)

**适用场景与可行动设计。** 技能/插件供应链审核应检查下游如何使用上游工件，尤其区分“事实/进度状态”与“权限状态”。高后果动作的授权需追到原始请求或可信授权源，不能由工作文件自证。评测同时记录实际效果、目的地、原文件身份、内容正确性、正常效用与成本；仅听Agent说完成或比较文件哈希都不足以证明动作授权。这些是防御设计推断，论文没有验证生产部署效果。

**可复现性、局限与判断。** 已读完整正文、主表、A–E附录、README、MIT许可证及上述评分源码；未安装、运行或独立复现，另静态抽查authority_contracts.py，权限声明与族别效果判定分开；它兼容旧评分路径，本轮未逐条对齐690个记录，不能用新版结构保证所有历史汇总。未审全部生成器/执行器。仓库有参考链、回放、评测及防御脚本，需另取SkillsBench、Python≥3.11、模型API；未见正式Release，14次提交不足以证明生产成熟。论文arXiv永久非独占许可与代码MIT不同，也不能扩展到全部依赖。跨技能混淆的机制证据较强，普遍攻击率、最终外发保证和防御稳健性证据有限。
