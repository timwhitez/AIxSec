## 最值得关注

1. **安全边界要落在副作用提交前**：Kairos 将可疑写入暂存，避免“先执行，再审核”，但论文的主要安全分数来自模拟工具适配器
2. **合法 JSON 也能改变错误的业务分支**：JevProbe 检查程序如何消费模型结果；其公开数据经过 flips-first 筛选，81.5% 不能当作无偏的现实攻击成功率
3. **补丁必须同时恢复安全与保留功能**：CWE-bench 的联合验收值得借鉴，但私有任务与模型/harness 混合比较限制了外部复现和模型归因
4. **靶场内高分不代表跨流量环境有效**：ACOG 的域迁移实验暴露失效，但尚不能证明自主防御 Agent 或 RL 已有效

<a id="paper-kairos-transactional-boundary"></a>
### 1. Kairos：在系统边界暂存副作用，再决定提交

**方向 / 类型**：Sec4AI / paper（含配套实现）  
**主题**：`agent-tool-security`、`prompt-injection`、`ai-security-evaluation`  
**日期 / 版本**：arXiv v1，2026-10-13；本期近期补读。仓库核查提交 `52563455095f3a1eaa882fe5717f02a347c32462`，提交日期 2026-10-08；未见 Release。论文状态按预印本处理，未核实同行评审接收  
**原文**：[Kairos: Transactional Security Enforcement at the System Boundary for LLM Agents](https://arxiv.org/abs/2610.18457)

**问题与新想法。** 工具调用后再审查，往往已经无法收回写入或发送。Kairos 将请求分为允许、拒绝与暂缓；暂缓操作保存在推测分支中，Agent 可继续工作，审核后才提交或丢弃。模型审核只能处理暂缓项，不能越过确定性拒绝。这个设计把“判断意图”和“允许外部效果发生”拆开。[方法全文](https://arxiv.org/html/2610.18457v1)

**实现与数据流。** 已读的 ReferenceMonitor 会把事件与参数来源送入策略引擎，用独立的分支状态保存暂缓调用。分支结算收集允许轨迹及先前结算信息，经 judge 和 commit gate 形成提交掩码，再执行获准调用；提交错误被记录，不应视为成功。文件信任账本用于阻止写出的不可信内容重新读入后被当成可信来源。这里值得复用的是显式的事件、来源、待提交状态和提交结果，而不是再加一句安全提示。[固定提交源码](https://github.com/UzL-ITS/Kairos/blob/52563455095f3a1eaa882fe5717f02a347c32462/kairos/monitor.py)

部署文档还给出 Cloud Hypervisor microVM、OverlayFS 暂存层、FUSE/virtiofs 文件边界及出站代理：文件变化先留在上层，网络副作用在代理处等待；需要立即取得响应的读取不能一概假装已完成。落地需要 Linux 虚拟化、网络代理与证书配置、模型访问以及对所有出口的完整控制，成本高于单个 Python 装饰器。[部署说明](https://github.com/UzL-ITS/Kairos/blob/52563455095f3a1eaa882fe5717f02a347c32462/deploy/README.md)

**证据及限制。** 作者在 GPT-4.1/AgentDojo 上报告攻击成功率 47.0%→2.7%，正常任务效用 82.7%→85.1%。把暂缓全部改为拒绝的消融，正常效用降至 42.7%，但该消融仅单次配置运行。重要边界是：主要基准使用内存工具适配器，并非真实 microVM 文件/网络端到端验证；长依赖链也可能因暂存返回值而受损。宿主和隔离层可信、所有出口受控等假设不能省略。[实验与威胁模型](https://arxiv.org/html/2610.18457v1)

**采用判断。** 可借鉴到授权 Agent 的提交门禁，先测试“拒绝、暂缓、提交失败、后续依赖”四条路径。来源传播还依赖值匹配，不能视为任意变换下的完备污点追踪。仓库提供复算材料，但部分对照数字来自论文导入；未据此宣称独立复现。代码许可证已核为 [AGPL-3.0](https://github.com/UzL-ITS/Kairos/blob/52563455095f3a1eaa882fe5717f02a347c32462/LICENSE)，需要结合复用方式评估义务。[仓库与复现说明](https://github.com/UzL-ITS/Kairos)

**证据判断**：机制和公开实现边界置信度高；安全收益为作者实验，生产迁移置信度中，未做独立运行验证

<a id="paper-jevprobe-consumed-decisions"></a>
### 2. JevProbe：从输出格式正确，走到业务决策是否被劫持

**方向 / 类型**：Sec4AI / paper（含配套实现）  
**主题**：`prompt-injection`、`ai-security-evaluation`  
**日期 / 版本**：arXiv v1，2026-10-13；近期补读、预印本。仓库核查提交 `9cec1be6ee57cc9872626222ba99739c8fcca610`，2026-10-13；未见 Release  
**原文**：[Nudge the Judge: Uncovering Program Decision Hijacking in Real-World Jev Applications](https://arxiv.org/abs/2610.18612)

**问题与新想法。** 当模型返回布尔、枚举或概率，schema 校验可以全部通过，应用仍可能走错分支。JevProbe 沿数据流寻找模型判定可接触的外部输入，用相同状态的原始/修改输入成对执行，观察应用实际消费的判定是否跨越阈值，而不只看文字输出改变。[论文全文](https://arxiv.org/html/2610.18612v1)

**实现。** 已读的 core 将案例身份绑定项目提交、调用位置、场景、初始状态和判定合同。比较器先按 decision ID 配对，再核对合同；概率越界、非有限数、枚举不合法或合同变化不能强行计成有效翻转。数值输出改变但没有跨过应用阈值，也与真正分支翻转区分。重复 decision ID 会报错，无法配对的结果保留不确定状态。[固定提交 core](https://github.com/xiaoxiaohg8d/JevProbe-/blob/9cec1be6ee57cc9872626222ba99739c8fcca610/jevprobe/ecosystem/core.py)

协议规定每案例一次基线、至多三次候选生成；无效生成占用尝试，不能靠无限重试洗掉失败。风险标注还要求基线对照、预先声明的独立正确性依据和消费节点证据。公开实现的实际损害字段保留为空，因此“潜在不安全结果”不能翻译成已经发生真实损害。仅保留原始字节再追加内容，也不能自动证明原语义保持不变。[协议](https://github.com/xiaoxiaohg8d/JevProbe-/blob/9cec1be6ee57cc9872626222ba99739c8fcca610/docs/PROTOCOL.md)；[风险证据实现](https://github.com/xiaoxiaohg8d/JevProbe-/blob/9cec1be6ee57cc9872626222ba99739c8fcca610/jevprobe/ecosystem/risk_criteria.py)

**证据要怎样读。** 论文报告 228 个可达应用、2,273 案例中的 1,853 次翻转（81.5%）。但公开基准说明明确：每项目最多保留 10 条，按 flips-first 选择代表项。因而这个比例描述筛选后案例集合，不能推广成全部尝试或所有应用的无偏攻击成功率。公开材料没有完整原始尝试账本；不能仅靠这份导出重建所有失败分母。一个输入还经过公开脱敏，其历史标签并非对脱敏后文本重新测得的结果。[基准说明](https://github.com/xiaoxiaohg8d/JevProbe-/blob/9cec1be6ee57cc9872626222ba99739c8fcca610/benchmarks/JevProbeBench/README.md)；[manifest](https://github.com/xiaoxiaohg8d/JevProbe-/blob/9cec1be6ee57cc9872626222ba99739c8fcca610/benchmarks/JevProbeBench/manifest.json)

**可行动启发与成熟度。** 防御回归应绑定真正的业务阈值、同状态基线和独立预期，分别报告格式失败、输出变化、决策翻转和潜在影响。涉及授权的关键动作仍需确定性权限检查。协议比一个“成功率”数字更值得复用。仓库需 Python 3.11+、部分场景的 Node/Bun 以及模型接口；未核实完整运行预算，未运行测试。[README](https://github.com/xiaoxiaohg8d/JevProbe-)；[MIT 许可](https://github.com/xiaoxiaohg8d/JevProbe-/blob/9cec1be6ee57cc9872626222ba99739c8fcca610/LICENSE)

**证据判断**：程序消费边界和公开集选择方式可由源码/文档确认，置信度高；普遍风险比例与实际损害不能由该筛选集推出

<a id="paper-cwebench-joint-verification"></a>
### 3. CWE-bench：漏洞修复须同时通过安全和功能合同

**方向 / 类型**：AI4Sec / paper  
**主题**：`code-security`、`security-agents`、`cyber-model-evaluation`  
**日期 / 版本**：arXiv v1，2026-10-12；近期补读、预印本，未核实同行评审  
**来源**：[论文页](https://arxiv.org/abs/2610.17020)；[方法、实验与附录](https://arxiv.org/html/2610.17020v1)

**机制与结果。** 作者在真实开源仓库注入新漏洞，构造 120 个私有任务，覆盖 73 类 CWE、8 种语言。Agent 得到威胁模型而非漏洞位置，在一小时内修改仓库；成功必须同时通过安全检查与功能检查，不能靠关闭功能拿分。参考补丁须通过两类检查。11 个模型与 harness 组合各做四次尝试，共 5,280 次；最佳 pass@1 约 68%，最佳 pass@4 约 81%，二者不能混当单次可靠性。另用三名 Agent 裁判复核，最终与程序判分一致率 93.9%，仍存在分歧。[全文](https://arxiv.org/html/2610.17020v1)

**判断与落地。** 工程团队值得借鉴“安全负例 + 合法行为正例”的联合验收，并保留超时的最终补丁和失败分母。这是本文启发，不是我们已复现的收益。私有任务阻碍外部重跑；模型和工具框架同时变化也不能归因于模型本体。裁判一致不等于真实安全真值，注入新漏洞也不能保证原仓库知识从未进入训练。当前未获得公开完整任务、验证器及其复用许可，不能把它介绍为可直接部署的开源基准；总推理成本未在本次阅读中可靠量化。

**证据判断**：评测合同和作者结果置信度中；外部复现、真实漏洞迁移、基础模型排名均保留

<a id="paper-acog-domain-shift"></a>
### 4. ACOG：防御训练环境首先要经得起流量分布变化

**方向 / 类型**：AI4Sec / paper  
**主题**：`detection-response`、`cyber-training-environments`、`cyber-model-evaluation`  
**日期 / 版本**：2026-10-13 arXiv v1；近期补读。IEEE CSR 官方议程列有 2026-08-03 报告，因此是较早会议工作新公开的 arXiv 版本  
**来源**：[论文页](https://arxiv.org/abs/2610.18594)；[全文](https://arxiv.org/html/2610.18594v1)；[官方议程](https://www.ieee-csr.org/2026-conference-program/)

**机制与证据。** Kathará/Docker 承载真实网络软件，YAML 驱动正常活动和固定攻击链，输出 PCAP 及 26 维流特征。实际实验为监督式 DNN 入侵检测，并非完整 RL/LLM 防御策略。相同网络在四种流量场景交叉测试：a 域训练后，a 域 F1 为 0.88，到 DNS/UDP 主导的 d 域降至 0.27。UDP 比例从约 20% 升至约 90%，同时流规模、类别比例变化，不能称严格单变量或“微小变化”实验。论文未明确 F1 平均方式。[方法与图表](https://arxiv.org/html/2610.18594v1)

**训练与复现边界。** 采用分层训练/测试划分和交叉熵分类；文中未清楚说明预处理拟合范围及时间/会话隔离。只有一种拓扑、固定攻击链和一个 DNN 架构，缺少重复方差及生产外部验证，未给出完整自主防御奖励与策略实验。未找到作者提供的完整代码/数据入口或许可，算力成本也不充分。[全文](https://arxiv.org/html/2610.18594v1)

**可行动启发。** 训练前置数据工程可先增加冻结的跨协议、时间与环境评测集，分别审计标签比例、预处理拟合范围及会话重合；将域内指标与域外指标分开。这是可借鉴的验证设计，不要求开展实际训练，也不能据此宣布自主防御能力提升。全文某一场景假阴性率的正文与图示不一致，本期不采用该数值；不将未下载到实现解释成作者没有实现。

**证据判断**：域迁移失败由作者图表支持，置信度中；泛化因果、RL 能力及开源可复现性未获确认

## 共同结论与阅读边界
