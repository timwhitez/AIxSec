### 1. MCP-FSD：工具合同与进程文件权限之间的缺口

**方向 / 类型**：AI4Sec + Sec4AI / paper  
**标签**：`vulnerability-discovery`、`agent-tool-security`、`data-exfiltration`、`ai-security-evaluation`  
**原文**：*My Credentials, Please: Detecting Filesystem Capability Laundering in MCP Servers at Scale*  
**作者**：Zeqian Huang、Mingyue Tang、Aonan Guan、Qiming Sun、Pengzhou He  
**版本与日期**：arXiv:2610.22301v1；2026-10-15 17:48:10 UTC，即北京时间 10-16 01:48:10；新预印本

**论文机制与证据。** 本地 stdio 工具的用途描述未必约束其进程权限。MCP-FSD 用 LLM 从实现推断工具与路径边界，在边界外放合成标记，比较“无隔离越界调用、隔离内正常调用、隔离内同一越界调用”。作者报告 150 个工具—策略实例，136 个有精确标记证据；787/4,806 只是分类与文件能力不一致筛选。缺少完整动态测试分母及边界推断准确度，不能计算普遍漏洞率；威胁模型从已发出的工具调用开始，不证明端到端诱导成功。[版本记录](https://arxiv.org/abs/2610.22301v1) · [全文方法、结果与局限](https://arxiv.org/html/2610.22301v1)

**上游交叉核验，注意是旧事件。** 维护者的 Git MCP 通告提供了更具体的权限语义：
- CVE-2025-68143 涉及本应围绕指定仓库工作的服务仍暴露初始化其他仓库的能力；维护者移除了 `git_init`，修复版本为 2025.9.25，通告发表于 2025-12-17。不能把它称为今天新发现的漏洞，也不能把论文作者等同于通告原始报告者。[维护者通告](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-vjqx-cfc4-9h6v)
- CVE-2026-27735 的边界在文件暂存：旧实现通过 GitPython 索引操作处理文件，未把相对路径可靠限制在仓库内；维护者改由 Git 命令处理，修复版本为 2026.1.14，通告发表于 2026-02-25。这是特定工具、具体版本的证据，不能外推为全部 MCP 服务的缺陷。[维护者通告](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-5cgr-j3jf-jw3v)

**如何借鉴。** 对自己维护的工具，先由负责人写出工作区、只读依赖目录、允许输出的位置，再拿这份人工批准的清单测试；不要让被审计工具的自述同时充当权限真值。输入应包含一次正常任务、一次边界外合成资源访问及对应启动配置；输出保留实际访问路径、返回证据和正常任务是否完成。正常调用通过，只能说明这个样例没有被阻断，不能证明允许目录选得正确。对存在状态变化的工具，应从相同初始快照做成对比较，避免前一次调用改变后一次结果。以上为本文建议的授权验收流程，并非已实施测试。

**证据状态与缺口。** 论文测量是作者报告；旧漏洞的影响与修复版本已由维护者通告交叉核对。此次未定位到可确认对应 MCP-FSD 的公开实现入口，不能宣称已审计其代码、许可证或复现成本。对“存在工具用途与进程权限落差”置信度高；对自动边界推断质量、总体发生率与跨平台效果仍不足。历史通告也不能独立验证论文全部 150 个实例。

### 2. LLM4SAST：用可检查的变换关系测试 SAST 工具

**方向 / 类型**：AI4Sec / paper  
**标签**：`code-security`、`vulnerability-discovery`、`cyber-model-evaluation`  
**原文**：*Combining LLM and Dynamic Analysis for Universal Testing of Static Application Security Testing Tools*  
**作者**：Huaien Zhang、Yu Pei、Hao Chen、Shin Hwei Tan  
**版本与日期**：arXiv:2610.21309v1；2026-10-15 05:57:29 UTC，即北京时间 10-15 13:57:29；新预印本

**论文机制与证据。** GPT-4o 依据种子与变换关系生成保义、修复或注入缺陷的程序；编译及动态反馈过滤不合格变体，再比较 SAST 报告并按程序差异聚类。六款 Java/Rust 工具中作者报告 66 个缺陷；消融保持缺陷数，误报候选从 23 降至 12。动态运行仅覆盖执行路径；Statfier 的语言移植及变换集合差异使“倍数提升”不能代表同成本优势。摘要称 32 个确认或修复，表 2 却列 12 fixed + 24 confirmed，状态计数存在不一致。[版本记录](https://arxiv.org/abs/2610.21309v1) · [全文方法、消融及表 2](https://arxiv.org/html/2610.21309v1)

**一个可以独立追到维护者的案例。** LockBud [issue #110](https://github.com/BurtonQin/lockbud/issues/110) 于 2025-03-03 提交，截至本次核查仍为 Open。报告展示 `Rc<RefCell<Vec>>` 持有数据时，分析器把临时借用结束误判成底层对象释放。维护者次日只表示会调查，并猜测工具链变化破坏了假设；2025-09-03 协作者进一步承认检测逻辑漏掉该场景。前者不是补丁完成，后者也没有把 issue 变成已修复状态。[维护者原评论](https://github.com/BurtonQin/lockbud/issues/110#issuecomment-2911373181) · [协作者后续判断](https://github.com/BurtonQin/lockbud/issues/110#issuecomment-3247423058)

**瓶颈为什么值得注意。** “生成一个变体后报告变了”至少有两种解释：分析器错了，或者生成器把被测性质改坏了。工程上应把两类责任分开，保留变换前后的程序、预期性质、独立检查结果以及分析器版本。聚类可以减少重复审查，但一个代表样本被确认，不自动确认整簇所有变体。对于生命周期问题，还要记录运行时对象关系，不能把变量名相同或文本相似当成语义相同。这里的建议来自对测试验收条件的分析，不表示本期运行过 LockBud。

**复用条件与限制。** 若将这类样例用于 Cyber 模型训练，建议按原始项目和种子家族划分训练/测试，避免同一个错误只换变量名就跨集合；并保留独立工具或人工确认，不能用被测 SAST 自己生成训练真值。该建议不意味着论文做过 SFT 或污染审计。论文给出的项目站点在本次访问中未成功打开，未核实可归属作者的代码仓库与许可证，因此不能称为已验证可一键复现。对测试思路的可解释性置信度中高，对缺陷总量、确认率与部署成本仅保留作者报告；不采用有冲突的确认数。

<a id="paper-linguaguard-controlled-language"></a>
### 3. LinguaGuardBench：控制语言变量，仍须控制统计单位

**方向 / 类型**：Sec4AI / paper  
**标签**：`prompt-injection`、`adversarial-robustness`、`ai-security-evaluation`  
**原文**：*Language Is a Security Surface for Agent Guards*  
**作者 / 机构**：Hasan Demirkiran、Jens Ernstberger / Kontext  
**版本与日期**：arXiv:2610.22244v1；2026-10-15 17:19:40 UTC，即北京时间 10-16 01:19:40；作者元数据称获 NeurIPS 2026 AIWILD Workshop 接收，非主会接收声明

**机制、实验与边界。** 研究只翻译用户请求，保持英语轨迹、工具调用和标签不变，以英语改写、空白变化及重复运行作对照。1,220 个步骤来自 589 条轨迹、仅 58 条独立请求；19 个守卫并非全部覆盖所有语言。作者报告 Nemotron Nano 9B 的阿姆哈拉语召回相对英语下降 7.4 个百分点。翻转可能纠错，不能直接当成功攻击；按轨迹重采样也可能低估按请求聚集的误差。“混语言不一致”是事后解释。未找到可核验的制品地址，释放声明不能代替代码/数据许可核查。[版本与接收声明](https://arxiv.org/abs/2610.22244v1) · [全文及附录](https://arxiv.org/html/2610.22244v1)

**防御回归应该怎样补齐。** 对有多语言用户的产品，我建议建立四格测试：请求与轨迹分别保持原语言或切换语言；同一请求的授权对象、资源范围、否定词、数量和时间约束必须逐字段对齐。若只翻译一个输入通道，就只能回答那个混合输入条件下的问题。评价时分别输出安全任务被拦、危险动作被放行、总判决变化，以及重复调用自身的波动；不要让它们共享一个模糊的“鲁棒性”数字。

**可借鉴条件。** 这适合调用工具前的守卫验收，前提是能够冻结被审核步骤，并由理解对应语言的人检查授权含义。对无法进行母语审阅的语种，反向翻译可以辅助发现问题，但不能独立签发语义等价证明。对于共享同一初始请求的大量步骤，应按请求族统计不确定性，再另报步骤级风险暴露量。以上是本文提出的下一轮验证设计，不是作者已经完成的实验。

**证据判断。** 本期仅核查公开论文，未独立运行或取得其完整制品。对“语言应成为守卫回归维度”的实践建议有明确动机，但不能从有限任务得出所有模型、所有语言的安全排名；也不能因为某些测试存在冗余上下文，就在真实产品中删去用户授权信息。

### 4. From Detection to Decision：校准分数，还要评估实际复核器

**方向 / 类型**：Sec4AI / paper，含配套工程核查  
**标签**：`prompt-injection`、`ai-security-evaluation`  
**原文**：*From Detection to Decision: Calibration and Deferral for Prompt-Injection Detection*  
**作者 / 机构**：Qianlong Lan、Anuj Kaul、Vinothini Pandurangan、Indranil Sanyal / eBay  
**版本与日期**：arXiv:2610.20907v1；2026-10-14 20:34:51 UTC，即北京时间 10-15 04:34:51；早于上期截止，明确列为**近期补读**，不冒充今天新闻

**论文问题与结果。** 输出概率不等于能可靠决定放行、拦截或复核。作者在 47,611 个留出样本上比较 Jev、两款 Prompt Guard 2 和 LLM judge；Jev 原生概率与其他模型目标分布校准并不对称。真实复核器级联的测试曲线上，FNR≤1% 对应超过 91.8% 转交，并伴随高误报；该观察点不是可直接部署的阈值。温度校准改善概率拟合不增加排序能力，不能据此证明更强检测。[版本记录](https://arxiv.org/abs/2610.20907v1) · [全文实验及局限](https://arxiv.org/html/2610.20907v1)

**源码揭示输入、处理与输出。** 已核查公开仓库 [lanqianlong/calibrated-decision-models](https://github.com/lanqianlong/calibrated-decision-models)，固定提交 `4c30771c7d8c07890884d596512251a7cf03157e`（2026-10-01 UTC）。输入是冻结的样本 ID、标签、预测概率和参数文件，非重新调用在线模型。温度模块将概率转为 logit，用单个正温度最小化校准集 NLL；转交模块按照距离 0.5 的不确定性排序，整组处理并列值，再以同一 ID 对应复核器的实际预测替换原决定，更新混淆矩阵和转交率。[温度源码](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/src/temperature.py) · [级联源码](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/src/security_deferral.py)

| 门模型 | 转交率 | 误报率 FPR |
| --- | --- | --- |
| PG2-86M（校准） | 91.89% | 40.55% |
| PG2-22M（校准） | 92.45% | 43.69% |

**真正可复用的验收细节。** 复现入口检查 split 数量、ID 唯一性、预测 ID 集合与确认集一致、概率有限且在有效范围；评价代码继续核对标签与逐样本对应关系。输出与发布的 JSON 参考结果作实质比较，且拒绝覆盖已有输出目录。开发、reviewer 校准、gate 校准、可行性及最终确认集分别固定；成本配置为误报 1、漏报 100、复核 0.5，是研究设定，不是通用业务成本。[复现脚本](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/scripts/reproduce_all.sh) · [方法参数](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/docs/METHOD_PARAMETERS.md)

**复现边界与许可证。** 该仓库是离线概率制品的指标重算包：不含原始提示文本、模型权重或推理客户端。原始数据需分别获取并遵守上游许可；仓库 MIT 许可证不自动授权再分发所有原数据。依赖为固定版本 NumPy、SciPy、scikit-learn、Matplotlib；核查时 Release 和 issue 列表为空，不能据此认定长期维护或无缺陷。README 仍使用较早的副标题及匿名引用提示，引用论文应以 arXiv 版本记录为准。[README](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/README.md) · [数据边界](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/docs/DATASETS.md) · [MIT 许可证](https://github.com/lanqianlong/calibrated-decision-models/blob/4c30771c7d8c07890884d596512251a7cf03157e/LICENSE)

**落地判断。** 在自己的业务上，要预先锁定阈值再进入后续时间段验证，同时报告正常请求基率、复核容量、尾延迟和复核器自身错误。ID 不重叠只能排除记录级重复，不能证明语义家族没有泄漏或模型训练未见过基准。把所有不确定样本交给“永远正确的人工”会低估真实错误；全部拒绝也可能以极高误拦换取低漏报。因此需给出整个系统的成本—风险曲线，而非单一校准误差。代码与文档可核验性高；数字仍是作者冻结制品与论文报告，本期未运行重算，也未做独立在线模型评测。
