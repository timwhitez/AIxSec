## 1. SESAA：模型维护规则，扫描不必一直依赖模型

**方向 / 类型**：AI4Sec · paper（近期补读）  
**来源 / 日期**：Rui Melo 等，*Self-Evolving Static Analysis via LLM Pseudo-Labeling*，[2610.30184v1](https://arxiv.org/abs/2610.30184v1)，首次提交 2026-10-20 10:17:26 UTC / 18:17:26 北京时间。  
**标签**：`code-security`、`vulnerability-discovery`、`security-agents`、`cyber-model-evaluation`

### 问题、机制与证据

静态扫描漏检常来自规则没跟上框架，而直接让模型逐次审代码难留下可复用产物。SESAA 让 Agent 编辑 Joern 查询；另一模型阅读命中与疑似漏检，形成伪标签和修正规则的票据。候选查询重跑后按代理评分保留，最终输出可独立运行的规则，不更新模型权重。覆盖类别只是召回代理，不是真实召回。[方法](https://arxiv.org/html/2610.30184v1)

作者在 Python OWASP 的 1,230 个合成案例上做 8 次运行，平均 F1 0.742，95%区间[0.671,0.812]，调优 CodeQL 的0.70落在该区间内；预算不匹配。移除 critic 的 F1 差异未显著，不能把收益全归于评审循环。真实仓库试点命中10/19个后续CVE，但不是线上零日发现。单次约254M Agent输入token，成本不低；预训练污染和人工基准线索仍可能存在。[实验与限制](https://arxiv.org/html/2610.30184v1)

### 可借鉴的最小设计

**本报建议**：先把现有审计中的重复发现转成“候选规则＋触发实例＋不应命中的近邻实例”，不要一开始替换整个扫描器。每次变更同时检验新增覆盖和旧规则退化；模型评审只生成待核事项，不直接作为规则准入的真值。

例如，SQL参数绑定中的用户值与拼接进SQL语句的用户值应成为成对回归。规则是否抓住了危险数据流，比它在一个文件中“附近有用户输入”更重要。最终准入应使用不参与规则搜索的项目/时间切分和人工确认样本。

**判断与缺口**：这是 harness/规则维护改进，不是 Cyber 模型后训练成果。机制有实用价值，但没有足够证据声称优于成熟工具；本次未找到可核验的该研究独立代码发布与许可，不能写成可直接安装的成熟开源产品。

## 2. SecLog-Bench：先证明发生了什么，再判断攻击到了哪一步

**方向 / 类型**：AI4Sec · paper（含公开实现核查）  
**来源 / 日期**：Yifan Wang 等，*SecLog-Bench: A Scalable Benchmark for Cybersecurity Log Reasoning with Scaffolded Evidence*，[2610.31000v1](https://arxiv.org/abs/2610.31000v1)，2026-10-22 09:41:16 UTC / 17:41:16 北京时间；投稿 IEEE TDSC，未确认接收。  
**标签**：`detection-response`、`cyber-training-data`、`cyber-training-environments`、`cyber-model-evaluation`

### 机制与结果

仅见可疑请求和HTTP成功码，不足以证明执行。该工作从29个模拟场景收集主机、应用与网络日志，关联并压缩成带引用坐标的证据窗口；评估准备、执行、结果三个具体阶段，另设“阶段无法闭合”类。216个人审窗口每类54项；“阶段无法闭合”既不是正常流量，也不是第四个真实攻击阶段。标签和参考论证只供评估方使用。[正文](https://arxiv.org/html/2610.31000v1)

完整216窗口上，八模型中最佳准确率44.44%；这是已筛出的攻击相关窗口推理，不是从海量日志发现攻击的检测率。同一GPT-5.4、同一96窗口中，相同压缩证据由平铺改为结构化呈现，准确率29.17%升至50%，关键错误率39.58%降至16.67%。这支持输入组织的重要性，不证明模型本体变强或泛化到未知场景；跨模型推理预算未匹配，96窗口结果也不能直接与216窗口排行榜比较。[实验](https://arxiv.org/html/2610.31000v1)

### 源码核查：引用重合不能冒充推理正确

本次固定[3eaa1a4](https://github.com/SecLog-Open/SecLog/tree/3eaa1a4787fac737faf0a19ec2a8e1efaa982264)，提交日期为2026-10-23。仓库的[基础评估器](https://github.com/SecLog-Open/SecLog/blob/3eaa1a4787fac737faf0a19ec2a8e1efaa982264/05_benchmark_annotation_review_evaluation/evaluation/evaluate_stage_reasoning_predictions.py)按样本ID关联，缺失预测记为不正确，额外预测另报；引用集合重合率及其四象限明确只是诊断，不能冒充论文正式推理可靠性。

[正式工作流](https://github.com/SecLog-Open/SecLog/blob/3eaa1a4787fac737faf0a19ec2a8e1efaa982264/05_benchmark_annotation_review_evaluation/README.md)先独立于模型答案建立阶段条件清单，再给两位独立评审盲化材料。标量分歧超过0.30需人工裁决，未解决不能进入正式评分；无效回答仍保留。这比只核验“有没有引用”更接近证据审计。

### 使用条件与可行动判断

[代码MIT](https://github.com/SecLog-Open/SecLog/blob/3eaa1a4787fac737faf0a19ec2a8e1efaa982264/LICENSE)，[基准CC BY 4.0](https://github.com/SecLog-Open/SecLog/blob/3eaa1a4787fac737faf0a19ec2a8e1efaa982264/SecLog-Bench-216/README.md)，不要混用许可。评估已有数据与重建采集环境是两条路径：前者可使用冻结JSONL和自有推理服务；后者需要Linux、Docker及抓包权限。公开Releases列表本次为空，不等于仓库没有可用数据；本次未重建Docker场景或下载验证Zenodo材料。

**本报建议**：先复用证据ID、缺失/无效输出保留、标签与解释分评分三项合同。若把数据用于SFT，应另设按场景和执行来源隔离的训练/验证/测试，不能拿同一216窗口既训练又宣称独立提升。该论文没有提供模型训练收益，参考论证也不应被直接视为无噪声训练真值。

## 3. AfterDeleteBench：删除需要覆盖派生状态，而不只是源记录

**方向 / 类型**：Sec4AI · paper  
**来源 / 日期**：Ehsan Saleh 等，*AfterDeleteBench: Auditing Post-Deletion Information Persistence in LLM Agents*，[2610.31366v1](https://arxiv.org/abs/2610.31366v1)，2026-10-22 14:41:36 UTC / 22:41:36 北京时间。  
**标签**：`model-privacy`、`agent-tool-security`、`ai-security-evaluation`

### 机制、比较和局限

模型权重固定，研究比较“接触秘密后删除”与“从未接触”的成对世界。主实验故意保留由原记录逐字拼接的摘要；因此是在可控外部记忆中定位残留，不是揭露商业产品删除失效。Qwen单问恢复差值为IID68%、合成OOD64%，各200样本，未接触组均零。[正文与附录](https://arxiv.org/html/2610.31366v1)

另用分散组件和公开拼接规则，测试没有完整秘密字符串时的重建；三个模型×两种分布，每组104个成对样本，恢复差值61.5%–99%。完整来源追踪下删除/重建后代，观察恢复为零，但不证明语义遗忘。写入过滤只能挡再次写回，不能撤回已输出的秘密。旧输出合同要求嵌套字段、评分却读顶层字段，存在漏计风险；历史原始答复未保存，不能追认当时具体泄露，后续确认实验才保留原答复并对齐合同。代码称待论文接收后公开，尚不能独立复现。[复现声明](https://arxiv.org/html/2610.31366v1)

### 可行动启发

**本报建议**：删除验收至少分四层：原记录消失、派生摘要/索引失效、当前回答不能重建、全新会话不能再取出。必须同时保留“从未输入秘密”对照，否则可能把模型猜测误判成记忆残留。

不要只用完整字符串扫描证明清除成功，也要测试拆分字段和可组合线索。来源闭包是可解释的工程起点，但会碰到混合来源、语义改写、缓存和历史备份；对无法完全覆盖的路径，应准确描述删除范围而非给出彻底遗忘保证。

**证据判断**：对受控残留通道的存在性证据清晰；真实系统覆盖、删除成本和正常任务损失仍未建立。这里不是训练集机器遗忘，也没有更新模型参数。

## 4. AgentPhishing：危险行动倾向必须与“认出钓鱼”分开测

**方向 / 类型**：Sec4AI · paper  
**来源 / 日期**：Justin Tan 等，*AgentPhishing: A Benchmark of LLM Email Agents Under Adaptive Attack*，[2610.31404v1](https://arxiv.org/abs/2610.31404v1)，2026-10-22 15:07:49 UTC / 23:07:49 北京时间。  
**标签**：`prompt-injection`、`agent-tool-security`、`ai-security-evaluation`

### 背景、机制与证据边界

传统邮件分类高分不等于代理不会顺手执行来信请求。PhishOpt在虚构身份、占位秘密和良性对照约束下，根据目标反馈优化可复用生成提示，而不是训练模型权重；再以未参与优化的模型检查迁移。被测对象输出动作和回复草稿，评分不执行外部操作。[方法](https://arxiv.org/html/2610.31404v1)

既有邮件集在六模型中均得到安全处理，自适应材料则暴露差异。保留模型实验每单元20邮件（含良性对照），同批跨模型复用；检测/服从率只以钓鱼邮件为分母，样本规模限制结论。检测定义包含归档、忽略等动作，不能等同模型真正识别；“服从”含选择点击或危险草稿，不能写成已盗取凭据。措辞消融只覆盖有限目标，综合分数去项是重评分，非重新优化实验。[实验与附录](https://arxiv.org/html/2610.31404v1)

### 防御侧如何使用

**本报建议**：邮件代理的验收分成“理解来信”“提出动作”“授权核验”“工具接纳”“实际副作用”五段。模型说可以回复，不应自动获得发送私密信息的权限。无论来信怎样表达熟悉关系或既有工作安排，都应回到独立的收件人、数据范围和用户授权核验。

评估应加入无害业务邮件，以同时测误阻断；自适应红队只在授权、合成环境中开展。将开发攻击、选择提示和最终测试拆开，并保留全部失败尝试与预算，避免选择最成功提示后再把同批结果称作泛化。

**成熟度**：论文CC BY 4.0；本次未确认该工作可用的公开代码仓库及其许可、完整推理费用。价值在测量设计，不宜以单条排行榜选择生产代理，更不能从动作模拟推断现实受害规模。

## 综合落地顺序与选稿说明

1. 先固定观测和评分合同：原始回答、输入证据版本、无效结果、预算均保留。
2. 再加可回滚的规则/证据组织层，分别验证命中率、误报和任务效用。
3. 最后评价实际授权和副作用边界，不能由草稿、引用或摘要替代。
4. 用独立项目、时间和场景切分做最终验收；以上属于本报工程建议，不是作者已验证的统一系统。
