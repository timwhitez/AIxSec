## 最值得关注的结论

**安全工程的关键不只是模型变强，而是结论由什么证据支持。** 本期分别检查四个环节：证明目标是否真的覆盖安全性质；日志能否支持事故因果；授权事实缺失时是否先恢复；上下文增益究竟来自提示词还是程序图。

1. [形式化验证](#news-formal-proof-contract)：模型生成证明可以由独立内核验收，但不等于整个库正确，更不自动保证终止。
2. [AgentTriage](#paper-agenttriage-evidence)：把事故诊断变成可重放证据链，公开案例却不足以复算全部论文成绩。
3. [EpiSEM](#paper-episem-missing-evidence)：不给错误信息，仅删掉授权事实，也能改变执行安全；补事实后仍需同时测合法任务完成。
4. [Harness 上下文消融](#paper-harness-context-ablation)：工程提示词与 CodeQL 同时改变时，不能把总收益都归因于程序图。

## 1. Anthropic × Theorem：证明的是固定构建下的性质，不是“这个库没有漏洞”

**方向：AI4Sec｜类型：技术报告与公开工程补读｜原文日期：2026-10-22**  
**标签：code-security / vulnerability-discovery / cyber-model-evaluation**

### 背景、机制与证据

Fuzzing 不断找反例，但没有发现崩溃不证明所有覆盖输入都安全。这项研究把 OSS-Fuzz 入口编译为 RISC-V 二进制，把失败条件写成定理，由 Claude 生成 Rocq 证明，再由独立内核检查。作者报告完整实验覆盖 123 个库、239 个入口；公开证明仓库目前是 **25 个库、60 个入口**，两者不能混用。小任务实验中，Opus 5.5 达到半数任务成功所需 token 比 Opus 5 少约 40%，但不代表通用审计能力提高 40%。[官方报告](https://www.anthropic.com/research/formal-verification)

公开来源链固定上游版本、harness、构建和目标定理；验收还检查证明类型以及允许的假设。关键改变是模型不再同时充当答案生成者和最终裁判。接入指南要求安全检查失败时明确 abort，避免会被 NDEBUG 消除的 assert；提供覆盖见证，再用破坏性质的变异确认检查确实会失败。这是在防止“证明一个根本没有检查安全性质的程序”。[证明来源与检查](https://github.com/theorem-labs/oss-verify-proofs/blob/main/docs/origin.md) · [接入规范](https://github.com/theorem-labs/oss-verify/blob/main/.claude/skills/add-project/SKILL.md)

### 保证范围、成本和复用

公开仓库明确指出没有证明 halts，因此 **不能排除无限循环**。agreement 类定理是覆盖条件下普通构建与 sanitizer 构建的行为关系，不是所有功能、所有平台或未来版本都正确。LPS 模型还限制单线程、信号、文件系统与外部进程行为；真实部署若不满足这些假设，不能直接继承保证。[定理解释](https://github.com/theorem-labs/oss-verify-proofs#what-a-proof-does-not-say) · [模型范围](https://github.com/theorem-labs/rocq-linux-process-semantics/blob/main/SCOPE.md)

附录的小型效率实验把输入限制为 64 字节，使用 mini-ASan，不能等同完整生产库成本；大任务证明检查也可能耗费数十分钟至数小时 CPU。证明生成时允许修改程序，因此还要独立检查补丁是否保留原功能，不能只奖励“更容易证明”。[技术附录](https://www-cdn.anthropic.com/files/4zrzovbb/website/6867eadf760258fa8b42a504600cd3c036d16358.pdf)

仓库自有工具、文档和证明为 MIT，派生证明及上游 harness 各保留原许可，部分 harness 标为 NOASSERTION。复用前逐文件核许可，不把“公开可读”理解为统一授权。[NOTICE](https://github.com/theorem-labs/oss-verify-proofs/blob/main/NOTICE)

**本文判断与可行动启发：** 适合先在高价值、窄接口、确定性依赖上试点。验收包应同时包含规格、覆盖见证、变异失败见证、构建指纹、模型假设和证明结果。若用于训练奖励，先约束补丁的功能等价和规格质量，否则“删功能换证明成功”可能成为捷径。这是工程建议，不是本文已经验证的训练方法；官方结果也不是与专家或 fuzzing 总成本的全面公平对照。

## 2. AgentTriage：用调用身份与来源图重建事故，而不是让 LLM 猜日志含义

**方向：AI4Sec / Sec4AI｜类型：论文与实现补读｜日期：2026-10-22，arXiv v1，未核得录用信息**  
**标签：detection-response / agent-tool-security / ai-security-evaluation**

### 问题与核心结果

Agent 的最终回答不能证明工具究竟执行、失败还是被拦截。AgentTriage 将跨运行时轨迹转为版本化证据契约，固定输入后可不调用模型重算诊断。159 次是采集运行数；准确性评测使用另一个 120 例裁决集。作者报告 GJD 为 0.858，最强同接口 LLM judge 为 0.683，配对差值 0.175、95% CI [0.092, 0.258]。这些数字不等于所有真实事故都能被完整发现。[论文方法与实验](https://arxiv.org/html/2610.30738v1)

### 从源码看数据如何流动

- **规范化关系：** ParentLinker 使用显式父关系、同 call_id 生命周期和字段来源，避免仅因两条日志相邻就直接建立因果。采集端提供的关系是否可信，仍需另行保证。[linker.py](https://github.com/AsnGs/agenttriage-open-source/blob/7f3ab28f08677b5ba9e54e41e16212aaa6e677a3/agenttriage/canonicalize/linker.py)
- **围绕结果切片：** GraphSlicer 优先选 sink_result，其次调用，再选防御终点，沿反向边找祖先子图；没有终点则标记证据不足。这样有助于避免把并发调用 A 的参数拼到 B 的结果上，但错边仍会导致错结论。[slicer.py](https://github.com/AsnGs/agenttriage-open-source/blob/7f3ab28f08677b5ba9e54e41e16212aaa6e677a3/agenttriage/stpg/slicer.py)
- **策略与事实分开：** 归因引擎区分允许、条件授权、阻断、违规及证据不足；LLM attribution 默认关闭，开启时不是隐式请求模型，而是未实现错误。[engine.py](https://github.com/AsnGs/agenttriage-open-source/blob/7f3ab28f08677b5ba9e54e41e16212aaa6e677a3/agenttriage/attribution/engine.py)

### 接入前不能略过的版本问题

静态读取 pipeline.py 发现：只有指定 annotation/reference semantics 版本关闭 expected_sink_family 对终点选择的偏好；其他兼容路径仍可能传入该字段。因此，不能把任意默认示例运行等同论文冻结评估，更不能让参考答案暗中影响待测终点选择。接入时应冻结语义版本，并用不含标签的轨迹检验结论是否改变。[pipeline.py](https://github.com/AsnGs/agenttriage-open-source/blob/7f3ab28f08677b5ba9e54e41e16212aaa6e677a3/agenttriage/pipeline.py)

公开材料包含 53 个行为案例的一次重复和 40 页无标签证据，排除了完整标注、裁决、参考答案、分数及部分计时代码；“能重放案例”不等于“能复算全部论文统计”。诊断本身无需模型，但重采集真实运行时可能需要 Docker、模型服务及相应费用。[公开案例说明](https://github.com/AsnGs/agenttriage-open-source#public-case-data)

代码为 Apache-2.0，上游快照保留各自许可；已读契约与管线测试源码，未执行。核查提交为 7f3ab28（提交时间 2026-08-14），未见 release，不把提交日期当首次公开日期或今日更新。[第三方许可](https://github.com/AsnGs/agenttriage-open-source/blob/main/THIRD_PARTY_NOTICES.md) · [契约测试](https://github.com/AsnGs/agenttriage-open-source/blob/main/tests/test_public_contract.py)

**本文判断：** 最值得借鉴的是审计工单契约：调用身份、参数来源、生命周期状态、政策版本和支持结论的最小证据一起保留。确定性只解决“同输入同结论”，不能解决传感器漏报或不可信日志。若将这些诊断用作训练标签，必须把缺证据与真实安全分开，避免把 unknown 当负样本真值。

## 3. EpiSEM-Bench：没有恶意提示词，缺掉一条授权事实也可能出错

**方向：Sec4AI｜类型：论文补读｜日期：2026-10-22，arXiv v1，预印本**  
**标签：agent-tool-security / ai-security-evaluation / safety-post-training**

### 方法与关键证据

EpiSEM 构造 300 组允许/禁止双世界任务。两边任务目标相同，但决定许可的事实不同；删除事实时持续移除所选事实的全部已标注普通工具暴露位置，后台世界和规则不变。RE 设置另加独立恢复工具，合法查询返回缺失事实。它测的不是提示注入，而是证据不完整时的行动。

同 mask 对照下，作者报告 GPT-6-Luna 的不安全任务占比下降 18 个百分点、合法完成增加 15.5 点；DeepSeek-V4.1-Flash 分别为 −36.3、+24.2 点。UCR 分母是 300 个任务，只要某个已测 mask 出现违规便计入，不是所有 rollout 的违规比例。PUR 要求恢复全部遗漏事实、无无效动作，并在允许世界合法完成、禁止世界弃答或升级；两模型为 30.5%、58.4%。设置为 12 步、请求 temperature 0、每条件一次 rollout，不能解释为稳定概率保证。[正文及附录](https://arxiv.org/html/2610.31650v1)

### 为什么这种设计有价值

**本文分析：** 只测“有没有执行危险动作”，全拒绝的 agent 也可能得高分；只测合法完成，盲目执行又可能占优。成对世界迫使评测同时回答“该停时停、该做时做”。例如请求内容不变，仅授权范围不同，合理行为应随可核验事实变化，而不是随模型的谨慎口吻变化。

这为安全后训练提供的是一种 **评测与样本组织思路**，不是论文已证明的权重训练收益：可在自有授权任务中建立完整世界、缺失证据投影、独立恢复来源与最终动作 oracle；保留成功、误执行、过度拒绝和工具失败，而不只收录漂亮轨迹。建议按任务族和政策模板隔离开发与最终评测，防止只记住模板；奖励必须同时约束禁止行为与合法效用，不能只奖励调用审计工具的次数。

### 复用边界与下一项检验

作者的恢复接口确定性返回全部遗漏事实，是理想化前提。真实系统应单独测试恢复源不可用、过期、相互矛盾或权限不足，否则“增加一次查询”可能并未恢复可信证据。不同模型的自适应 mask 覆盖数不一致，比较效果应使用匹配条件，不把原始失败总数直接排名。

本轮未核得可公开取得且许可明确的完整数据/实现包；论文可阅读不等于数据获授权用于训练。真正落地前需先核发布物、数据许可和来源，再评估工具请求数与端到端成本；增加核验交互并不保证每次都产生合法完成。本文仅提出上述验证设计，没有训练或复现实验。[版本与许可入口](https://arxiv.org/abs/2610.31650)

## 4. 漏洞发现 Harness 消融：别把好提示词的收益记在 CodeQL 账上

**方向：AI4Sec｜类型：论文补读｜日期：2026-10-20，arXiv v1**  
**标签：vulnerability-discovery / security-agents / cyber-model-evaluation**

### 背景与实现：拆开混在一起的变量

论文基于 DeepSec 的“静态筛选 → Agent 调查 → 独立会话自复核”流程，再增加根因归并、不同模型家族的源码复核和隔离 PoC 确认。主要目标是匿名生产 TypeScript API 网关的固定版本，约 150 个候选文件；24 个模型—运行器配置各跑两次。这里“独立复核”不等于全部由独立人类团队复现。[论文方法](https://arxiv.org/html/2610.28802v1)

上下文实验选四个模型、八种条件，固定筛选和自复核，只改变调查环节。A0 是简短提示词，A1 增加漏洞分类、严重度、误报和缓解检查；之后才加调用图、按需图查询、配置文档或 CodeQL 结构。CodeQL 提供函数、调用关系和局部数据流等线索，**不是运行完整全局污点分析**。因此“图中可达”仍不能直接证明攻击者输入会到达敏感操作。[实现与消融附录](https://arxiv.org/html/2610.28802v1)

### 真正有辨别力的对照

在同一个 A1 提示词上增加 CodeQL，每次平均确认安全根因数为：
- Gemma-4-31B：21 → 25.5。
- GPT-5.5：86.5 → 80。
- Composer-2.5：91.5 → 87。
- GLM-5.1：71.5 → 42。

所以“从 A0 到工程提示词加图，较小模型收益显著”与“图本身并非普遍有益”可以同时成立。数量下降也不自动说明整体价值下降，还要看误报和确认成本。不要把摘要里的组合收益归因给一个组件。[表 4 与表 11](https://arxiv.org/html/2610.28802v1)

### 证据等级、数据许可与迁移限制

265 个安全根因是所有配置观察到的并集，不是整个项目真实漏洞全集。主要评测只有一个匿名仓库、每格两次，跨模型还混入不同 runner；CyberGym 外部实验为 21 个已知漏洞文件且给出目标位置，不能等同整仓未知问题发现。成本未包含共享归并、独立审查与 PoC，不宜宣称端到端性价比已经证明。原模型自复核会漏掉有效发现，因此拒绝报告不能自动变成训练负标签。[实验与局限](https://arxiv.org/html/2610.28802v1)

论文页面注明 CAMLIS 2026 接收，正文 CC BY 4.0；基础 DeepSec 为 Apache-2.0，不能自动延伸到全部作者扩展。因负责任披露，目标身份、SHA、漏洞明细和 PoC 未公开。本轮未核得完整实验数据/扩展实现包，故它不是现成可下载的 SFT/RL 数据集。[论文状态](https://arxiv.org/abs/2610.28802) · [基础 DeepSec](https://github.com/vercel-labs/deepsec)

**本文判断与可行动启发：** 先冻结模型、提示词、上下文和验证器四个版本，做预算匹配的无图/局部调用链/图摘要对照，再决定是否增加基础设施。若产出训练数据，应保留原始报告、自复核拒绝理由、独立证据和复现结果，按证据强度分层，而非按模型语气分正负。后训练要与未训练、同 harness 基线比较，否则工具与提示词收益容易被误记为权重收益。

## 汇总：可复用的是验收契约，不是未经检查的数据包

- **证明链：** 目标性质、构建指纹、允许假设与功能保持检查一起验收。
- **诊断链：** 保留调用身份、来源、状态与政策版本，缺证据不冒充安全。
- **行动链：** 使用允许/禁止成对任务，避免全拒绝或盲执行在单指标上获胜。
- **实验链：** 分开模型、提示词、上下文、验证器与预算的贡献；保留失败和拒绝样本。

以上是基于公开研究的工程建议，不是四篇论文都已验证的统一训练方案。本期未新增模型后训练效果声明；亦未把论文许可等同完整数据许可。公开源码阅读、作者统计与独立实验三者严格区分。
