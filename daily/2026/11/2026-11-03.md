## 要点

有效的安全审批需要观察行为但不能突破隔离边界；检测器应按稀有攻击、未见工具和负样本组成验证；安全技能改写的收益必须连同退化与预算报告。

## 1. Caper：在隔离环境观察后果，再决定是否保留执行

**Sec4AI · paper · 2026-10-29 v1** · `agent-tool-security` / `ai-security-evaluation`

**问题与方法。** 审批器只看命令文本时，看不到脚本或 Makefile 内部行为。Caper 先快照每个任务的 Docker 容器，在禁网、内存与进程上限和超时约束下用系统调用跟踪执行；提取文件变化、输出、敏感路径读取、网络尝试等有界后果卡片。独立审批器允许时保留已执行状态和输出，不再执行一次；拒绝时丢弃变更容器并从快照恢复，返回脱敏原因。[论文方法 §4](https://arxiv.org/html/2610.40753v1)

后果卡片将同一进程中先前读取与后续输出关联，但这种“同主体先读后写”是启发式关联，不等于证明字节级数据流。预执行是真实执行，只有容器内状态可回滚；远程请求、外部服务与逃逸出的副作用不能倒退，必须先隔离或模拟。一次观测也不能覆盖随机、延迟或识别沙箱后的不同行为。

**证据。** 作者对 SABER 的 682 个 shell 任务，以及自建 YoloFS-Ext 的 102 个危险任务和 102 个安全孪生分别每任务运行一次。SABER 有害结果率 Caper 6.7%，六种基线至少14.8%；YoloFS-Ext 为7.8%，安全孪生误拦1.0%。但在 Claude Code hook 内分别是10.0%和6.9%，不能把两种环境混成一个数字。去除内容 diff 后 YoloFS-Ext 有害率从7.8%升至13.7%；更弱审批器在误拦上获益但危害并未同样下降。[实验 §5](https://arxiv.org/html/2610.40753v1)

中位审批3.2秒，沙箱每条允许命令约增0.5秒、拒绝约1.5秒，API成本每任务0.019美元；这是作者特定实验而非部署报价。审批器与部分评分依赖模型；没有评估自适应分段攻击、时延触发或沙箱识别，shell之外的直接文件编辑也不由同一机制覆盖。

**落地启发（假设）**：授权测试中可将权限审批、隔离执行、可观测证据与不可逆副作用分层；对无网络、伪凭据、合成文件的安全孪生比较误拦、漏拦和完成率。不要把“可以回滚”当作允许先在真实环境运行的理由。

## 2. Agent 劫持检测：稀有攻击和未见工具让高分失效

**Sec4AI · paper · 2026-10-30 v1** · `prompt-injection` / `ai-security-evaluation`

**问题与机制。** 研究者检验事后工具调用轨迹检测器，而不是实时阻断。输入包括工具名称、调用序列或行为特征；另比较读取内容的文本模型和已发布动作监控器。作者在 AgentDrift 的合成轨迹上训练/定阈值，再按攻击比例重加权，并将测试工具逐步替换为未见工具，最后跨到 AgentDojo。[方法 §III](https://arxiv.org/html/2610.41803v1)

训练只见过已知工具时，序列模型的未知工具 token 没有得到训练；训练时随机遮蔽工具输入可减轻排名反转，但阈值漂移仍需单独校准。不同基准的工具、模型、任务及标签同时变化，不能把跨基准失败归因于某一项。

**证据与反证。** 作者审查11项相关评测，其测试异常比例16%–86%，均未变化该比例。一个组合检测器 AUROC 0.879，在假定攻击占2%、指定负样本混合及训练阈值下精确率仅0.076；负样本从正常到困难样本变化可使其精确率从0.117降至0.039。该2%是情景假设，不是真实部署基准率。训练于 AgentDrift 的检测器在 AgentDojo 上 AUROC 约0.47–0.52；未在两者训练的动作监控器可达0.930，但其提示此前曾在 AgentDojo 上评估，且稀有事件下误报仍高。[结果与限制](https://arxiv.org/html/2610.41803v1)

两基准可被模板或固定攻击字符串近乎分开；AgentDojo 攻击轨迹中模型分布不均，跨域也伴随多种变化。除该监控器外，多数分析计划是在探索结果后完成，不能全部称预注册前瞻验证。未独立复现。

**落地启发（假设）**：固定阈值之外同时报告按基准率分层的精确率、每千会话告警数、负例构成、未见工具覆盖率和跨场景对照；加入简单文本/长度基线检验捷径。事后发现不等于已阻止动作。

## 3. SKILL-SIF：用失败轨迹改技能，也要保留回归

**AI4Sec · paper · 2026-10-19 v1** · `code-security` / `vulnerability-discovery` / `cyber-model-evaluation`

**问题与方法。** 安全技能可能让 Agent 找到相关函数，却没有建立对象生命周期或锁顺序。作者用37种技能、四个底层模型，在100个 Linux 内核漏洞上进行14,800次运行；严格正确要求同时匹配 CWE、函数和语句。随后选前五个技能：以已知漏洞和失败轨迹诊断缺失证据或推理关系，汇总经验，修改 SKILL.md，在开发集重复运行、记录新增正确和回归，再冻结所选版本，用100个未用于迭代的漏洞做配对比较。改的是程序化指导，不是训练模型权重。[方法 §§3–6](https://arxiv.org/html/2610.25705v1)

**作者结果与反例。** 初始全部运行仅11.1%同时满足三项，函数定位24.4%，二者不能混用。新案例上2,000个技能–模型–案例组合的严格正确率由6.05%升至11.20%，个别组合由2%升至16%；但20组技能–模型中15组改善、两组不变、三组下降，不能把最大8倍当普遍收益。失败分类由模型提出，374例由两名人工分别标注，一致率77.8%，模型标签经裁决确认80.5%，并非无误真值。

选择前五技能、最高开发代数及最多10轮优化带来选择和额外推理预算，且仅文件引导的 Linux 内核及10类CWE；未知训练数据污染和跨生态效果。未确认公开实现、数据完整可获性或软件许可，论文 CC BY 4.0 不等于代码许可。没有等预算的人工作业或简单提示基线闭合，不把增益完全归因于自动进化。

**落地启发（待检验）**：为每轮保留原失败、候选变更、提升与回退，独立冻结从未用于选择的测试；按漏洞家族及仓库去重切分，以同模型、工具和总预算比较原技能、简单补充与迭代版本，报告绝对百分点和区间，而不只报告最大倍数。
