<a id="news-jetadmin-mitigation-status"></a>
### 1. Jet Admin：沙箱缓解与修复状态

**一句话结论**：新公开的是漏洞通告，不是新补丁；官方记录支持提示注入与凭据暴露风险，但不能据此断言缓解后的托管服务仍可稳定利用，或已经彻底修复。

- **原文**：*Jet Admin Cloud Platform Prompt Injection*，VA-26-317-01 / CVE-2026-123965。
- **发布者与时间**：CISA；CSAF 1.0.0 的首次发布字段为 **2026-11-13 16:45:20 UTC**；对应仓库提交为 17:09:33 UTC；CVE 记录发布时间为 17:12:17 UTC。三个字段不是同一种时间。
- **标签**：`prompt-injection`、`agent-tool-security`、`data-exfiltration`、`ai-supply-chain`。

**已确认内容。** CISA 描述：远程攻击者持免费账户，可通过提示注入暴露环境配置文件并外泄关键凭据。CVE 标为 exclusively-hosted-service，CWE-200；CNA 给出 CVSS v4.0 9.3、v3.1 9.9。分数表达严重性假设，不是攻击成功率或在野利用证据。[CVE 原始记录](https://github.com/CVEProject/cvelistV5/blob/main/cves/2026/123xxx/CVE-2026-123965.json)

**必须保留的状态差异。** 同一份 CSAF 在说明中写“约 10 月 29 日通过沙箱组件缓解”，但结构化 remediation 仍是 none_available / No fix available，产品状态仍使用所有版本受影响的宽泛范围。不能选择性引用其中一句，把整个产品宣布为“已修复”或“当前全部仍可利用”。厂商[更新日志](https://www.jetadmin.io/changelog)本次可读页面未提供可核对的具体沙箱版本、部署覆盖或完整修复声明。[CISA 通告固定快照](https://github.com/cisagov/CSAF/blob/0a86b7171466c448c1b2d776c0cda9e8938451d0/csaf_files/IT/white/2026/va-26-317-01.json)

**技术边界。** 原始通告没有公开足以还原完整调用链的细节。本报不推定它属于直接还是间接注入，不猜测沙箱底层实现，不声称观察到跨租户攻击，也不提供利用提示词或凭据读取步骤。记录中的 SSVC “Exploitation: none”来自 11 月 6 日判断，不能当作今天仍无利用的实时证明。

**本报分析。** 真正需要验收的是注入后可触及的资源边界：执行环境是否含生产密钥，文件可见性如何划分，网络出口是否受限，敏感动作是否经过独立授权。模型拒绝危险请求是一层控制；让执行环境根本无法接触不应读取的数据，是另一层控制。对于托管服务，客户还需要供应商给出缓解覆盖范围、验证时间和历史暴露处理依据，不能照搬“升级到某版本”的本地软件流程。这里列的是通用防御检查方向，不是已证实的 Jet Admin 实现缺陷。

**证据与许可。** 官方协调通告事实置信度高；当前各租户风险和缓解有效性证据不足。本报未测试服务，也未见独立复现。CSAF 标记 TLP:WHITE，属于公开通告；托管平台本身不是本报核验过的开源项目。

<a id="paper-caplite-write-integrity"></a>
### 2. CapLite：写入完整性与任务损失

**一句话结论**：让模型提出计划、由代码检查写入权限，能减少“模型写错授权规则”的风险；代价是对隐含目标和动态工作流很保守。

- **原文**：*CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts*。
- **作者与版本**：Zimo Xu、Wenzhuo Liu、Hideki Nakayama；arXiv:2611.17115v1，**2026-11-12 17:07:22 UTC** 提交。
- **标签**：`prompt-injection`、`agent-tool-security`、`ai-security-evaluation`。

**机制。** 威胁模型信任用户请求、工具和工具文档，只把返回文本视为可被攻击者控制。固定规则从工具 schema 派生字段角色；模型在看到工具结果前承诺写入计划，之后只能绑定候选参数。确定性 Mediator 要求收件人、金额、对象或目的地等权限字段精确来自请求，或取得用户确认；未知工具默认拒绝。它约束的是执行写入，不是保证生成文本正确。[论文全文，方法与威胁模型](https://arxiv.org/html/2611.17115v1)

**结果与分母。** AgentDojo 的 15 个模型 × 929 个工具目标任务中，作者报告攻击成功 **0/13,935**；每模型另外 20 个纯回答目标不计入此分母。受攻击任务效用为 29.0%，CaMeL 为 27.2%，无防御为 50.2%；平均 token 为 17.1k，对比 CaMeL 的 93.7k。不能把 token 减少直接称作相同比例的价格或延迟改善。[摘要及版本记录](https://arxiv.org/abs/2611.17115v1)

**保证没有覆盖什么。** 论文明确允许注入影响自由文本载荷、时间字段和最终回答，并展示纯回答注入成功案例。它也会拦住某些合法任务：用户只描述收件人而没给出具体地址时，运行中查出的地址不能自动变成授权。评测不回答追加确认，因此这类交互被算作失败。各基线被移植到同一小模型配置，结果不代表原系统在大型托管模型下的所有能力。

**本报分析。** 这里最有价值的区别是“计划格式正确”与“计划获得授权”。即使解释器忠实执行，模型自己生成的权限策略也可能把错误动作合法化。CapLite 收紧了这一点，但字符串出现在请求中，仍不应在更一般的产品中自动视为用户同意其所有用途。落地时需要人工审查工具副作用和字段角色，尤其不要把有安全含义的枚举、时间或文本字段当作无害。对需要动态发现目标的工作流，合理交互和确认设计应与安全指标一起验收。

**可复现与置信度。** 论文 CC BY 4.0；作者称发布代码和逐任务结果，但本次未定位到可确认归属的实现仓库及许可证，因此不声称代码已核实开源。同名无关项目不作为证据。方法与指标口径可核对，广泛有效性仅有单一基准和作者实验，未独立复现。

<a id="paper-small-model-ranking"></a>
### 3. 小决策模型：候选排序与验证成本

**一句话结论**：小模型可以帮助决定先看哪里，但排序得分不能替代漏洞结论，搜索吞吐也不能替代完整验证成本。

- **原文**：*Look Here, Then Decide: Small Decision Models in a Harness Find Memory-Safety Vulnerabilities at Scale on Commodity GPUs*。
- **作者与版本**：Tim De Wachter、Kyryl Volkov、Myrto Eleftheria Gkogkou、Mathieu Huysman；arXiv:2611.16565v1，**2026-11-12 09:51:23 UTC** 提交。
- **标签**：`code-security`、`vulnerability-discovery`、`cyber-model-evaluation`。

**机制与关键负结果。** 确定性规则从 C/C++ 代码与历史修复中定位候选，既有 Intern-Decision-4B 给候选排序，没有新的 Cyber 微调。71 对漏洞/修补函数与 200 个良性函数上，模型区分漏洞与普通良性代码 AUC 0.731，但区分漏洞与自己的补丁仅 0.564。外部于发现项目的 75 个公开 CVE 中，16 个进入仓库前 25 名，随机次序期望 11.1 个；不是宣传中的普遍 7.5 倍。[摘要和版本记录](https://arxiv.org/abs/2611.16565v1)

**证据需要拆开。** 7.5 倍来自已知含确认发现的 51 条队列，且研究员按模型排序审查，有选择偏差。187 项确认发现还经过更强编码模型、sanitizer 与强化构建复现及人工审查，不能归功于纯 4B 自动流水线。RTX 4090 的 9.8 decisions/s 是 278 次决策子任务吞吐，验证费用和研究员时间没有完整记账。作者明确暂不公开候选、研究框架与 PoC。[论文全文，实验和限制](https://arxiv.org/html/2611.16565v1)

**模型材料。** [Intern-Decision-4B 模型卡](https://huggingface.co/internlm/Intern-Decision-4B)可读，基于 Qwen3.5-4B，标注 Apache-2.0。模型一次前向计算对预设答案打分，不需要生成长解释；其概率校准数据与一般任务结果不能自动证明对漏洞候选已校准。模型可获得，与本研究完整审计流水线可复现是两件事。论文自身 CC BY 4.0。

**本报分析。** 对安全训练最有用的启发是把“漏洞对普通代码”和“漏洞对自身补丁”分开测。前者可能捕捉危险代码的外观，后者才更接近理解修复改变了什么。部署时应保留低分队列和抽样审查，不轻易把排序阈值变成永久丢弃门槛；还应统计候选生成、队列上限、评分和确认各阶段的损失。未进入候选集合的缺陷，再好的排序器也救不回来。

**边界与置信度。** 搜索阶段不使用前沿模型，不等于确认阶段也不用。复现崩溃不等于证明产品正式入口可达，更不等于逐项确认代码执行。原文限制于 C/C++ 内存安全，不能外推业务逻辑漏洞；本报未确认全部发现的厂商状态，不公开未披露细节。方法和数字有原文支持，完整成本优势、普遍召回与可迁移性仍未证实。

<a id="paper-crossploit-version-evidence"></a>
### 4. CrossPloit：历史版本与执行证据

**一句话结论**：受影响版本表是待验证的知识，不是绝对安全边界；跨版本实验也必须证明触发的是同一漏洞，而不是环境错误或新引入缺陷。

- **原文**：*CrossPloit: A Benchmark for Cross-Version PoC Migration in Python Web Applications*。
- **作者与版本**：Hung Nguyen-Huu、Nguyen Anh Tuan、Ting Zhang 等；arXiv:2611.16588v1，**2026-11-12 10:21:05 UTC** 提交。
- **标签**：`code-security`、`vulnerability-discovery`、`security-agents`、`cyber-model-evaluation`。

**任务与验收。** 127 个迁移实例覆盖 45 个 Python Web CVE，给定参考 PoC、固定环境、公告、补丁和目标源码，以漏洞特定 oracle 与因果复核检查历史版本。九模型、两种 Agent 框架各运行一次；最佳 Opus-4.6/OpenHands 完成 **74/127（58.3%）**，VulScope-Web 基线为 **11/127（8.7%）**。构建中确认的 149 个未列出旧版本包含 22 个无需迁移即可复现的实例，不能与 127 个迁移任务混为一谈。[摘要及版本](https://arxiv.org/abs/2611.16588v1)

**比较不完全对称。** 基线只调整输入，不能像 Agent 一样修复环境或 API；验证流程也并非完全相同。因此差距不能只归因于模型更会推理。一个配置同时去掉参考 PoC 与环境说明后，从 64/127 降到 19/127；这不是单独移除“漏洞知识”的消融。任务是正例集，不能从成功率推出误报率。[论文全文，实验与限制](https://arxiv.org/html/2611.16588v1)

**本报分析。** 这一基准适合回答“能否在授权环境中确认历史版本暴露”，不适合直接回答“能否自主发现零日”或“能否准确扫描任意生产部署”。对构建训练环境而言，oracle 应检查漏洞根因与可观察效果，而不只接受进程退出、错误消息或 Agent 的自述。训练/测试划分还应避免同一 CVE 的相邻版本跨集合泄漏；本研究是能力评测，本报不把它描述成已有受控训练方案。

**复现、成本和证据边界。** 全文提供实验协议，但本次未定位到公开基准下载、完整代码与可复用许可证，不称为开源基准。论文采用 arXiv 非独占分发许可。一次运行、重叠类别和正例选择限制了统计推广；验证者相互复核仍是研究团队内部判断，不等于第三方复现。不能把单配置成功率换算成真实漏洞管理的节约成本。本报只描述评测方法，不提供具体迁移载荷或针对目标的操作步骤。

## 横向判断

四项材料可以归纳为两个需要分别验收的问题：

- **权限是否明确**：Jet Admin 提醒我们检查实际运行环境的资源可达性；CapLite 则把写入目标和模型生成内容拆开。两者都不能只靠“模型通常不会这么做”作为安全依据。
- **证据是否够用**：小决策模型的排序收益，不等于漏洞确认能力；CrossPloit 的版本迁移成功，也不等于泛化到所有漏洞。数据选择、分母、工具权限和验证成本应一起报告。

这是本报综合分析，不是四份来源共同作出的结论。
