## 1. Origin：从 Agent 轨迹回查代码入口

**Sec4AI · paper · 2026-11-19 v1，预印本补读**  
标签：`agent-tool-security` / `ai-security-evaluation` / `detection-response`

**问题与新想法。** 运行轨迹说的是“读资料、写报告”，静态分析工具说的是变量、函数与调用。如果两边没有映射，分析员必须先猜哪段代码对应日志，才能问“这份数据从哪进来”。Origin 在两层之间加一张图：把源码区域映射到 Agent 功能，再用变量依赖把区域连起来。相比直接运行通用静态分析，它先回答“查哪几块”，再回答“沿哪条路径回查”。[原文与版本](https://arxiv.org/abs/2611.26525) · [方法](https://arxiv.org/html/2611.26525v1)

**机制。** 系统用 Joern 构建 Python 的代码和变量依赖图，并用 Pyrefly 类型信息补一部分间接调用；少量外部调用和内部来源先由开发者审阅标注。调查时，分析员用轨迹找出可疑功能，先在功能区域图缩小范围，再选候选变量或操作查数据依赖。输出是能回到源码的候选函数路径，不是模型生成的事故故事，也不是运行时观测到了每条边。跨进程或多阶段存取还需人工用共同数据对象和日志接上证据。[实现](https://arxiv.org/html/2611.26525v1#S8) · [案例流程](https://arxiv.org/html/2611.26525v1#S9)

**证据与局限。** 作者让分析员调查五个开源 Agent 的八个选定案例，八个都找到预设的单一入口；五个案例用两次查询，其余三个用四次。区域查询返回完整变量图的 **6.49%–35.76%** 节点，不等于已测得相同比例的人工耗时下降。Joern/CodeQL/Pysa 对照已知源和汇，且 Pysa 的成功标准是路径上至少一个正确调用，不是同一端到端任务。小样本、开发者参与标注、运行时动态行为难静态解析，都限制外推；没有已核的现场告警精度。报告可复用的是日志字段：保留代码版本、功能区域、事件或对象 ID 与可复核的来源边界；缺少运行证据时把图边标为候选，不把静态可达性写成实际发生。[表 3–5](https://arxiv.org/html/2611.26525v1#S9) · [归因和边界](https://arxiv.org/html/2611.26525v1#S10)

## 2. PhantoMasq：车载异常检测不能只看 ROC

**AI4Sec · paper · 2026-11-19 v1，预印本补读**  
标签：`detection-response` / `cyber-model-evaluation`

**问题与机制。** 单条车载 CAN 消息看起来正常，不代表它和周围消息一起出现时正常。PhantoMasq 把固定帧数的观测窗口变成图：消息标识是节点，连续消息之间的有向转换按频次加权，节点附上解码信号的均值和标准差。两层图卷积让节点交换邻居信息，全图均值汇总后判别窗口。与先单独学习浅层图嵌入、再训练分类器的方式相比，这里分类损失直接调整图特征；但对照同时存在其他差异，不能把所有成绩归给这一项。[原文与版本](https://arxiv.org/abs/2611.26094) · [模型和切分](https://arxiv.org/html/2611.26094v1#S6)

**证据。** ROAD 数据来自一辆实车的台架采集，整个数据集超 3.5 小时；本评估采用 13 份含异常采集和一份背景流量。作者先在采集的各区域按时间切分，再构建重叠窗口，避免同一帧进入训练和测试；每配置五个随机种子。五类平均 ROC-AUC 为 **0.831–0.999**，最难一类 PR-AUC 仅 **0.218**，而正例窗口占 **5.4%**。后者胜过随机基准，但不能用前者宣称在低误报下可用。同一窗口网格的外部基线切分、特征与分类器不同，难类的基线最佳分反而更高；不能宣称所有条件胜出或把差距归因于图卷积。[结果和对照](https://arxiv.org/html/2611.26094v1#S7)

**落地边界。** 在 Apple M4 CPU、单窗口推理下，模型本身约 **0.15–0.38 毫秒**，含建图与信号统计的窗口计算约 **2.33–5.94 毫秒**，不含等到窗口填满的时间，不代表车载控制器延迟。同车同采集的切分不是新车或新采集的验证；离线还排除了跨真值边界的窗口。先做按整次采集或车辆留出的验证，追加变化边界的召回、误报/小时和从事件起到告警的总延迟，再考虑上线。该文是窄任务监督分类，不是 Cyber 大模型能力提升。以上为作者报告与本文工程判断，未运行代码、模型或实验。[讨论](https://arxiv.org/html/2611.26094v1#S8)
